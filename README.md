# itofu（糸譜変換）

五線譜の楽譜データ（MusicXML）を入れると、弾きやすい調弦の候補3案と、糸譜(箏の楽譜)が自動で出てくるWebアプリ。
58ハッカソン2026（テーマ「ito」）の作品です。

- **ペルソナ**：部活でJ-POPを弾きたいけど、五線譜を箏の楽譜に書き直すのが大変な人
- **使い方**：MusicXMLをアップロード → 調弦の候補3案（そのまま／バランス／押し手ゼロ）から選ぶ → その調弦に合わせた縦譜が表示される

## 担当

| 担当 | 内容 |
|---|---|
| フロント担当 | 画面 |
| 解析担当 | ② 解析、④ 整形、API |
| アルゴリズム担当 | ③ アルゴリズム、Docker環境 |


## 全体の流れ

```
MusicXML
 → ② 解析：音のリストにする
 → ③ アルゴリズム：調弦の3案と、各音の弦・押し手を決める
 → ④ 整形：フロントと約束したJSONにする
 → API：フロントに返す
 → 画面：調弦の候補と縦譜を表示する
```

① 入口（楽譜の画像 → MusicXML）は余裕があれば。本体が動いてから判断する。

## 技術

- フロント：フロント担当が決める
- バックエンド：Python 3.14.8、FastAPI ＋ uvicorn、music21（MusicXMLの読み込み）
- 環境：Docker

## 動かし方

Docker環境は準備中。それまでは手元で次のように確認できる。

```
cd backend
pip install -r requirements.txt
python run_local.py
```

Docker環境ができたら、APIは http://localhost:8000 で動き、http://localhost:8000/docs からブラウザで楽譜をアップロードして結果を確認できる。フロント担当はDocker不要で、このAPIを呼ぶだけ。

## 箏の基本

- 弦は13本。奥から 一 二 三 四 五 六 七 八 九 十 斗 為 巾（一番手前が巾。番号は0〜12）
- 平調子（基本の調弦）：一を0としたときの半音差 `[0, -7, -5, -4, 0, 1, 5, 7, 8, 12, 13, 17, 19]`
- 押し手：弦を押して音を上げる。弱押し（ヲ）＝半音、強押し（オ）＝全音

## API

| メソッド | パス | 内容 |
|---|---|---|
| POST | `/api/analyze` | MusicXMLのファイルを受け取り、フロント用のJSONを返す |
| GET | `/api/health` | サーバーが動いているかの確認 |
| POST | `/api/omr` | （余裕があれば）画像を受け取り、MusicXMLを返す |

## 部品の間の約束

### ② → ③ 音のリスト（1音ごと）

- `midi`：音の高さ（休符はなし）
- `measure`：何小節目か（0始まり）
- `offset`：小節の中の位置（拍単位。0, 1, 1.5 など）
- `beats`：長さ（拍単位）
- `rest`：休符かどうか

和音は一番上の音だけ。タイでつながった音は1つにまとめる。

### ③ → ④ 調弦の候補（3案）

- `id` / `label`：A そのまま、B バランス、C 押し手ゼロ
- `tuning`：13本それぞれの音（midi）
- `base`：基音（一の音）
- `changes`：平調子から変えた弦と、何半音動かしたか
- `changedStrings`：変えた弦の本数
- `oshiCount`：押し手の回数
- `assignments`：音のリストと同じ順番で、各音の弦番号と押し手（0なし／1弱／2強）。休符は空

### ④ → フロント

`candidates`（調弦の候補3案）の中に、それぞれ `measures`（小節 → 拍 → 音の3段）が入る。1拍の中の音は、リストの順に上から縦に書く。

| JSON | 楽譜に書くもの |
|---|---|
| `{ "string": "七" }` | 七 |
| `{ "string": "九", "oshi": "ヲ" }` | ヲ九（弱押し） |
| `{ "string": "九", "oshi": "オ" }` | オ九（強押し） |
| `{ "string": "七", "repeat": true }` | 、（前の音の繰り返し） |
| `{ "rest": true }` | ⊙（休符・伸ばし） |

調弦の説明文（「平調子（一＝E）より六を全音上げる」など）は④で作る。

## ③ アルゴリズム

解き方はアルゴリズム担当にお任せ。箏のルールで分からないことは解析担当に聞く。

**弦の割り当て（assign.py）**
- 各音を、その音の弦をそのまま弾くか、半音下の弦を弱押し／全音下の弦を強押しして出す
- 押し手が少なく、手の移動（弦番号の差）が少ない弾き方が良い
- どの弦でも出せない音がある調弦は、良くない

**調弦の探索（tuning.py）**
- ルール
  - 各弦は、平調子の位置から上下1オクターブまで
  - 二〜巾は、隣の弦より低くしない（同じ高さはOK）
  - 一は例外：五と同じ音か、五の1オクターブ下
- 出してほしい3案
  - A そのまま：平調子のまま（基音だけ曲に合わせる）
  - B バランス：押し手と調弦替えのバランスが良い案
  - C 押し手ゼロ：押し手が0の案（無理なら最小）
- 押し手も調弦替え（平調子から変える弦の本数）も、少ないほど良い

## ④ 整形のルール

- 1マス＝1拍。1拍の中の音はリストの順に縦に並べる（grid.py）
- 長い音は、2拍目以降を休符（⊙）にする（grid.py）
- 直前の音と同じ弦・同じ押し手なら「、」にする（to_json.py）
- 弦番号を漢字（七など）に、押し手を「ヲ」「オ」に変換する（to_json.py）

## 作る順番

0. 環境：Dockerで起動すると `/docs` が開く（アルゴリズム担当）、`main.py` の土台とCORS設定（解析担当）
1. 型：`schemas.py` を作ってバックエンドの2人で確認
2. 並行して進める
   - 解析担当：`parse.py`。さくらさくらで音のリストが出る
   - アルゴリズム担当：`assign.py`。平調子に固定し、手で作った音のリストで動かす
3. つなぐ：parse → assign（平調子固定）→ grid → to_json → API。1案だけでもフロントにJSONが返る → フロントとつないでみる
4. `tuning.py`：3案が出る（アルゴリズム担当）
5. デモ曲で確認、改良、入口を入れるか判断
